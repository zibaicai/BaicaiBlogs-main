# 架构文档

本目录记录项目的长期架构契约，而不是临时实现细节。

## 阅读顺序

1. [产品与边界](./product.md)
2. [角色模型](./roles.md)
3. [不可违反的规则](./invariants.md)
4. [资源模型](./resources.md)
5. [前端架构](./frontend.md)
6. [后端架构](./backend.md)
7. [ADR 决策记录](./adr/)

## 文档职责

| 文档 | 回答的问题 |
|---|---|
| `product.md` | 这个产品是什么，谁是用户，边界在哪里 |
| `roles.md` | 谁能做什么，API 如何分层 |
| `invariants.md` | 哪些规则不能违反 |
| `resources.md` | 内容资源的所有者、状态、可见性和生命周期 |
| `frontend.md` | 页面、组合组件、基础组件如何分层 |
| `backend.md` | 控制器、服务、认证、授权如何组织 |
| `adr/` | 为什么做出某个关键决策 |

## 维护原则

- 架构文档优先于对话记忆。
- 代码和文档冲突时，先确认真实产品意图，再同步修正两者。
- 关键决策用 ADR 追加记录，不覆盖历史。
- 文档保持短小、可执行，不写成宣传材料。
