# 产品与边界

## 定位

本项目是一个**社区网站**，不是单人博客，也不是只给管理员使用的 CMS。

用户不仅是读者，也是内容生产者。每个注册用户都拥有自己的控制台和内容空间。

```text
C 端
公开浏览、阅读、互动、个人展示

Admin 控制台
所有注册用户的内容工作区
按角色开放不同管理能力

Backend
统一资源、权限、存储、审计
```

## 三类用户

```text
USER
普通社区用户

ADMIN
管理员，负责内容与社区治理

SUPER_ADMIN
超级管理员，负责系统级配置与高风险操作
```

角色只决定能力范围，不决定是否能登录控制台。

## 核心内容

```text
文章
笔记
说说
项目
相册
音乐
内部存档
```

所有内容资源都应具备一致的概念：

```text
所有者
状态
可见性
公开路由
管理路由
删除策略
审计要求
```

## 两个前端

### C 端

面向匿名用户、普通用户和搜索引擎。

```text
公开内容
SEO
阅读体验
互动
个人主页
```

### Admin 控制台

面向所有登录用户。

```text
普通用户：
  自己的内容、资料、统计

ADMIN：
  内容审核、举报、部分全局管理

SUPER_ADMIN：
  系统配置、授权、隐私审计、IP 封禁、内部存档
```

## 边界原则

- C 端不承担管理操作。
- 控制台不假设所有访问者都是管理员。
- 后端授权以资源和角色为准，不以前端页面是否显示为准。
- 外部平台抓取只负责导入，不把平台 DOM 泄漏到展示层。
- 公开内容和私有内容必须有清晰的路由与缓存边界。
